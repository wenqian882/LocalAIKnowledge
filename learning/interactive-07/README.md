# 输入问题，自动完成检索和消息组装

本轮把两段已有程序串起来，形成一个可以连续提问的学习工具：

**输入问题 → 调用本机向量检索 → 读取这一轮的真实结果 → 组装带来源的回答消息。**

当前只查02实验中的三份虚构样例，尚未读取自己的知识库或接通回答模型。不是桌面应用已完成自动RAG的声明。

## 使用

双击项目根目录 `运行交互检索练习.cmd`，输入一个问题，例如：

> 星灯工具可以调整界面字号吗？

等待本机检索，终端会显示参考原文、相似度，以及可粘贴消息文件的位置。可以继续输入另一个问题；直接回车退出。每轮单独加载模型和运行旧脚本，不需要启动常驻服务，也不承诺已做性能优化。

问题和结果写入 `%LOCALAPPDATA%/LocalAIKnowledgeLearning/interactive-07/<随机编号>/`，每轮一个新目录，包含 `retrieval.json`、`generation-input.json`、`paste-into-chat.txt`。不写入源码或现有Electron用户数据库，不覆盖旧实验报告。没有API调用；手动将消息发给已配置模型才会使用API。

## 本轮合并学习三个知识点

1. `input(...)` 接收输入，`while` 让程序连续处理问题。
2. `run_query(question, top_k, runtime)` 把一次完整操作组织成函数。
3. 用 `subprocess.run` 的参数列表调用已有检索器，再把输出文件交给已有消息构建器；没有拼接shell命令执行用户问题。

这体现的是数据流：后一段程序读到的必须是这一轮问题对应的检索结果，不能一直用之前写死的问题或旧报告。

按本人“Python只懂大概”的最新说明，`ask.py`每个非空代码行已补充行末中文注释，覆盖语法、参数、路径、字典和数据流。可从main中的输入/函数调用读起，再沿run_query查看调用过程。此次只增改注释并核对语法树一致，没有重跑模型、检索或桌面验收。

## 机器配置

本机已配置忽略提交的 `runtime.local`，只含现有Python解释器和公开ONNX模型目录。该配置仅在本机使用，不含API密钥。没有修改其所在项目的代码、私有资料或模型缓存。

其他机器把 `runtime.example.json` 的内容复制到 `runtime.local`，替换成已安装FastEmbed依赖的Python解释器和完整BGE缓存目录。基础Python用于启动入口；第三方依赖和模型复用[01实验说明](../embedding-01/README.md)。缺少本机环境会报错，不自动安装/下载。

也可用已配置的基础Python执行一条命令，处理一问后退出：

```powershell
python -X utf8 ask.py --question "星灯工具可以调整界面字号吗？" --top-k 1
```
