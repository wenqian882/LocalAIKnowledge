# 用这个项目学习 RAG

目标：能独立完成一个知识库问答系统，解释每一步的理由，使用固定测试发现问题，并验证修改是否有效。这里的验收是项目学习标准，不是企业统一门槛，也不保证就业结果。

这份路线适合 RAG 初学者，以实习或初级 AI 应用开发能力为目标。当前桌面应用由 Codex 辅助实现，代码存在或自动测试通过不代表学习者已经会写、能解释或能独立维护。

当前应用v0.7.0已提供DeepSeek/OpenAI API设置、本机TXT/Markdown/Word/PDF正文提取、300/600字符分块预览和当前文档的字面关键词检索；仍未接通基于资料的问答。本人已实际导入PDF、对照原件并通过复制文字参与定位异常空格，也手动找到了支持导出格式答案的项目段落；这些操作不代表独立接口开发、全文解析质量或RAG能力验收。学习继续每次一小步。

## 学习方式

每次围绕一个可操作的小任务推进：先体验界面里的现象，再解释相关概念，亲手修改一个小范围，最后验证结果。把“在终端执行的命令”和“在文件里修改的代码”分开说明；需要逐行讲解时，按行说明目的。不要从整份 Electron 源码或完整 RAG 框架开始背诵。

2026-11-17节奏更正：本人认为此前反复解释同一原则、每轮推进太少，明确要求加快。当前RAG教学改为一轮一个完整可运行的小功能，合并2—3个相关概念，代码改动/实际结果/必要原理在同一轮给出，不再每个微小概念都停下来等确认。遇到具体不懂的地方再展开；这不意味着基础或独立能力已经提高。

记录本人实际完成的动作、依赖的提示和仍不会解释的部分。按本人2026-11-16最新要求，已验收且未修改、未受影响的功能不重复验收；新改动只检查直接相关范围。迁移到另一份资料的独立练习在本人愿意继续时安排，不把反复操作旧功能设为继续学习的门槛。

## 评测集怎么逐步建

先人工核对 10～15 个问题，检查检索调试流程是否看得懂；再逐步扩展到 50～100 个认真核对的问题。包含普通问题、无答案问题、跨文档问题、近义混淆、文档更新和删除情形。这个数量只是学习建议。

每题保留：问题、预期有无答案、支持文档与原文段落、预期关键点、实际检索片段、实际回答、错误分类。优化对照时固定问题、资料版本与统计口径。不要用一个没有来源的“准确率”代替分析；没有“达到 90% 就就业”的通用保证。

先分别回答两件事：相关资料有没有进入候选片段？回答是否忠实于这些片段？后续再学习 Recall@k、排序指标与回答评估的适用边界。接触过验收指标不等于已经能设计、实现或解释检索算法。
