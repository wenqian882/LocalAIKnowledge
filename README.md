# LocalAI Knowledge

一个独立的本地 AI 知识库桌面应用。首版先做好聊天工作空间、资料管理和持久保存，为后续学习与实现 RAG 留出接口。

**v0.7.0 支持 TXT / Markdown / Word（.docx）/ 文字型 PDF 的本机导入、正文提取、300 / 600 字符分块预览与当前文档的关键词检索；尚未保存分块或建立检索索引，未接入基于资料的问答。** 聊天区保留两层模型设置，每条消息只调用一个模型，未配置时默认演示。桌面应用本地运行不代表模型本地运行；启用外部模型后，点击发送会将当前对话文字交给所选服务商，可能产生 API 费用，关联知识库文件不会随消息发送。

界面参照 DeepSeek 公开截图的聊天布局：浅灰会话侧栏、白色正文区，空白对话的输入框紧接问候语，已有消息时固定在底部。保留 LocalAI 名称和原创图标，没有复制第三方品牌素材或代码。 Windows窗口与打包EXE显式使用同一蓝色图标，源码测试窗口也保持一致。

## 粘贴 API Key

1. 点击左下角「设置」，选择 DeepSeek 或 OpenAI（ChatGPT 模型）。
2. 在 API Key 输入框粘贴自己的密钥；模型名称已预填，可按账户权限修改。
3. 点击「保存并启用」。这一步只保存到本机，不发模型请求。也可先点「测试连接」发送一条简短测试文字，可能产生少量费用。
4. 关闭设置，点击输入框旁的模型按钮，先看到推理强度/速度浮窗，再点其中的模型名选择服务商及模型，随后发送消息。两家密钥分别保存，不用每次切换重新粘贴；「切回演示模式」会停止后续外部调用，「清除已保存密钥」会移除当前服务商的本机密钥。

## 在聊天区切换模型

- 输入框旁显示模型名、推理档位和快速标识。点击打开、再点同一按钮收起小浮窗：中间显示当前强度、下方模型名，左侧闪电开关，右侧恢复默认；推理强度可用滑杆、键盘或滑杆内圆点调整；浮窗按参考截图收紧，闪电/重置图标缩小。收费与固定倍速边界可通过闪电悬停提示及无障碍说明读取。再点模型名进入第二层分组模型列表，可搜索、返回、点击外部或 Escape 关闭。
- 每次发送只用一个模型。选择影响后续消息，旧回答的服务商/模型标签保持；同一会话继续时，会把该会话文字历史发送给新服务商。
- 模型按固定参考顺序展示，切换不会把当前模型移到首位。DeepSeek 与 OpenAI 独立分组；额外账户/手填模型去重后按名称中的数字倒序放在预设之后，设置页使用同一顺序。
- 一个服务商的 Key 可配合多个有权限的模型 ID 使用。可选择预设、之前使用过的模型，或手动填写模型 ID；不需要为每个模型另存一份 Key。
- 点击某家「刷新模型列表」才会用其已保存的 Key 查询官方模型目录；只 GET 模型元数据，不发聊天、不调用生成。15秒超时，可停止，失败保留缓存；重启后可以离线选择已缓存的模型。
- 预设只提供快捷填写，未验证账户权限。目录根据模型 ID 初筛文本候选，不能保证每个候选都支持本应用使用的文本接口；实际权限、余额及接口支持以调用结果为准。无 Key 的服务商不可选择，可去设置粘贴。
- 打开选择器、选择模型、保存设置及启动应用不联网；只有显式刷新、测试连接和发送会访问对应官方端点。历史、知识库和两家原有加密 Key 在升级时保留。

推理和速度按每个服务商的每个模型分别保存，切换/重启后恢复，恢复默认只影响当前模型。设置强度/速度只写本机，不发请求；已有Key无需重新粘贴。OpenAI已明确适配GPT-6.1 Sol / Terra、GPT-6 Astra / Sol / Luna、GPT-5.6 Sol / Terra / Luna的推理档位，Sol 6.1和Astra不提供关闭推理档；DeepSeek Flash / V4 Pro支持关闭、低、高、最高。其他模型暂不显示未适配的推理控件，不猜测能力。默认沿用原低推理/DeepSeek关闭思考设置。

闪电为真实OpenAI API Fast模式，默认关闭，仅对已适配模型开放；选中后发送`service_tier: fast`，标准档明确发送`default`。Fast模式费用高于标准，实际速度取决于模型、账户与供应商，不提供固定1.5倍速保证，也不以加快文字动画冒充模型加速。DeepSeek及未适配模型快速开关禁用。GPT-5.6 Terra/Luna本版未适配Fast；模型权限与Fast可用性以实际账户为准，失败不自动降级或重复调用。API不返回可用于本应用界面确认的实际速度倍数，本版也不把请求档位写成已测得的加速效果。

实现依据[OpenAI模型参数](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[OpenAI Fast模式](https://developers.openai.com/api/docs/guides/fast-mode)与[DeepSeek思考参数](https://api-docs.deepseek.com/guides/thinking_mode/)。推理占用输出预算，强度提高可能更耗时/更多用量；若达到预算，可调低强度或缩短问题。当前只显示最终回答，不展示模型思维链。

模型目录接口依据 [OpenAI 列出模型](https://developers.openai.com/api/reference/resources/models/methods/list)和 [DeepSeek 列出模型](https://api-docs.deepseek.com/api/list-models/)。

OpenAI 使用 Responses API，预填 `gpt-4.1-mini`；DeepSeek 使用 Chat Completions，预填 `deepseek-flash` ，默认关闭思考，可在聊天区调整已适配模型的推理强度。模型可用性以服务商账户为准。两家地址固定为官方 HTTPS 接口，当前不支持第三方中转或自定义 Base URL。ChatGPT 订阅与 OpenAI API 分开计费，ChatGPT 登录密码不能用作 API Key。实现依据 [OpenAI 文本生成文档](https://developers.openai.com/api/docs/guides/text)、[DeepSeek 首次调用文档](https://api-docs.deepseek.com/)和 [OpenAI 计费说明](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)。

本版非流式，每次最多发送当前对话最近20条非演示消息、合计6万字符，不发送其他对话、文档正文或知识库元数据。输出预算4096 tokens，测试非推理128 tokens、启用推理1024 tokens（包含推理消耗，沿用该模型保存的强度/速度）；90秒超时，无自动重试，等待时可停止。取消或超时不保证服务商未计费。调用失败保留草稿且不保存失败消息，不回退成演示回复；真实路径的回复会标注服务商、模型和「未检索」。


## 启动

已打包的 Windows 版本：打开 `release/LocalAI Knowledge-win32-x64/LocalAIKnowledge.exe`，或双击根目录的 `启动应用.cmd`。保留整个应用文件夹，不能只复制其中的 EXE。无需浏览器、Python 或数据库服务器。当前 Windows 构建未签名，未提供自动更新或安装器。

从源码启动建议 Node.js **24 或更新的受支持版本**与 npm（PDF解析库声明Node 24）。本机系统Node 22.23.1构建通过；应用解析和单元测试实际使用Electron内置Node 24.22.2，不依赖用户额外启动服务。在项目目录的终端执行：

```powershell
npm ci
npm start
```

首次安装依赖、下载 Electron 运行时需要网络；应用正常运行不依赖网络。`npm start` 先构建本地资源，再打开 Electron 独立窗口，不启动 localhost 服务。

```powershell
npm run typecheck  # 类型检查
npm test           # 构建、存储测试、真实 Electron 窗口集成测试
npm run package    # 打包当前平台、当前架构的桌面文件夹
node scripts/test-portable.cjs  # 打包至项目外临时目录，验证Word/PDF可独立使用
```

目前只实际验收 Windows x64。其他系统可从源码尝试，不承诺已通过兼容性测试。集成测试需要可用的桌面会话，不是纯无界面服务器测试。

## 查看分块：一个可观察的 RAG 学习步骤

在知识库打开文档正文，点击「查看分块」，选择每块最多 300 或 600 个字符，对比块的数量和内容，观察标题与说明有没有被切散。字符数包含空格和换行，按 Unicode 码点计算，并非模型 token 数。

这是一套可解释的基础切分规则：每个窗口后半段优先找空行、换行、句末或空格，没有合适分隔符时按上限切开；保留原文字和位置，不添加片段重叠。规则不会理解项目归属，也不能保证每块语义完整。结果每页最多显示 20 块，避免大文件一次渲染过多内容。

这里只在本机内存中预览，不修改文档或导入记录，不写入分块表、不生成向量、不调用 API；关闭预览后重新计算。关联聊天仍不检索这些片段。

分块页的关键词框可查找**当前文档**的全部分块，包括当前页之外的块。输入一个词或连续短语，忽略首尾空白及英文字母大小写，保留原始块编号与原文顺序；清空后恢复全部结果。这里只做字面包含匹配，不做语义理解、同义词扩展、相关性排序或跨知识库搜索；关键词跨块也可能漏掉。未命中会提示换词或核对正文，不能据此断言资料没有答案或某项能力不受支持。

## 数据在哪里

Windows 默认位置：

```text
%APPDATA%/LocalAIKnowledge/
  data/
    knowledge.sqlite       # 知识库、导入元数据、会话、消息及模型来源、知识库关联
    model-settings.json    # 模型选择、已用模型与目录缓存、经系统加密的密钥
    knowledge.sqlite-wal   # SQLite 运行时可能存在
    knowledge.sqlite-shm   # SQLite 运行时可能存在
    files/<知识库ID>/<文件ID>  # 应用保存的原格式文件副本
    files/<知识库ID>/<文件ID>.parsed.json  # Word/PDF正文、PDF逐页文字、解析提示
```

「关于与数据位置」弹窗显示本机实际路径。其他系统使用 Electron 的 appData 根目录下 `LocalAIKnowledge`。用户数据不会写入源码仓库。测试使用独立临时目录和合成文档，不导入个人资料。

文件导入单个最多10 MB，每次最多100个；TXT/Markdown需UTF-8纯文本。Word支持现代`.docx`，旧`.doc`请在Word中另存为`.docx`；PDF支持已有文字层的文件，最多500页。每份正文最多200万字符，Word声明解压后总内容最多50 MB/单项20 MB，二进制文档解析超过30秒停止，工作线程JS堆限制192 MiB。这些是本版保护上限，不是吞吐量或最坏内存占用保证。同名文件可以分别导入，副本使用独立 ID，不相互覆盖。修改原文件不会自动同步到副本；当前需要移除旧副本后重新导入。导入列表中的「未索引」是实际状态，不存在后台索引任务。

Word/PDF解析使用本机工作线程，保留原格式副本，并缓存提取正文；界面不执行文档HTML、脚本、PDF动作或宏，不读取外部链接和图片文件。PDF中文字体映射与所需标准字体数据随应用分发，不向字体CDN请求。支持不等于完整还原：图片、复杂表格、文本框、页眉页脚、多栏和阅读顺序可能丢失，请对照原文；本版只显示纯文字。

无文字的PDF或图片型Word会明确提示未提取正文、尚无OCR，不伪装成功；部分PDF页面无文字时，保留已提取内容并标出页码提示。加密PDF要求先解密，损坏文件报错；不提供无法使用的密码/OCR入口。解析成功只代表有正文可查看，仍未建立检索索引，关联聊天不会自动发送这些正文。

SQLite自动兼容旧TXT/Markdown记录与聊天，新增解析格式、页数、字符数和提示元数据，数据库版本为3；旧文件不在启动时重新解析。移除文件会删除应用原格式副本、解析缓存及导入记录；删除知识库同样清理缓存，保留用户原文件和已有聊天。

关闭应用后，可整体复制 `data` 目录备份；恢复时同样先关闭应用，再整体恢复。数据库与文件副本需一起备份。聊天数据库和文件副本没有加密，本版没有多用户权限管理或在线同步；设备文件访问权限由操作系统管理。API Key 单独使用 Electron safeStorage 的系统加密保存，Windows 使用 DPAPI。加密不可用时拒绝保存，不降级为明文。它保护磁盘上的凭据，但不能防止同一系统用户下的恶意应用。密钥不回读到界面、不写入日志和聊天；换电脑或系统用户恢复后可能需要重新粘贴密钥。系统加密说明见 [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)。

## 数据边界与进程职责

```text
React 界面
  ↓ 类型化的有限接口（contextBridge）
Electron preload → 主进程 IPC → Store → SQLite / 应用文件副本 / 提取正文缓存
                                  ↘ ModelService → 官方模型API（显式测试/发送/刷新目录）
                                  ↘ 文档工作线程 → Mammoth / unpdf（PDF.js）→ 本地正文与页信息
                                  ↘ providers.ts（解析接口与未来检索接口）
```

主进程拥有数据库与文件系统权限。渲染进程禁用 Node 集成，启用上下文隔离和沙箱；只暴露列出的业务操作，不暴露任意 SQL、任意命令执行或任意读取路径。IPC 校验窗口与页面来源，数据库使用参数化查询。安全配置依据 [Electron 官方安全文档](https://www.electronjs.org/docs/latest/tutorial/security)。SQLite 使用运行时内置的 [Node SQLite API](https://nodejs.org/api/sqlite.html)，无需额外安装原生数据库插件；该 API 在所用运行时可能输出实验性提示，升级运行时后应重跑测试。

本版不包含文档上传、遥测、自动更新或联网资料搜集。渲染页面 CSP 与默认 Electron 会话始终阻止 HTTP(S)/WebSocket 请求；显式模型调用由主进程的独立网络会话执行，仅允许向两家官方生成接口发送 POST、向模型目录接口发送 GET，拒绝重定向。字体使用系统字体。默认启动和保存配置不调用模型，显式刷新目录、测试连接与发送才会访问所选服务商。文档正文按纯文本展示，不执行 HTML、脚本或文档指令。未来实现 RAG 时仍需把资料视为不可信上下文，不能把文档指令升级为应用权限。


[交互检索练习](learning/interactive-07/README.md)可通过根目录 `运行交互检索练习.cmd` 连续输入问题，串起现有本机向量检索和消息组装，结果保存在用户数据目录；只查虚构样例，不读取私人知识库或自动调用回答API。

1. 在独立练习中补齐 Python 文件、JSON、数据库与接口基础。
2. 在已支持的格式解析上练习清洗与质量核查，再做可追溯分块、文档版本与删除联动。
3. Embedding、单一向量存储、检索调试与来源展示。
4. 在已实现的显式模型调用上加入基于检索资料的引用回答、无依据时拒答。
5. 固定评测集、检索与回答分开评估、失败案例分析与优化对照。
6. 按测得的问题增加 BM25 / 混合检索 / 重排；之后再考虑OCR、更多格式与交付扩展。

Python 学习练习与未来后端应保持独立边界，不为首版增加常驻服务。详细学习任务见 [学习路线](docs/LEARNING_PATH.md)。不把本版 UI 或 Codex 生成代码当作学习者已掌握 RAG 的证据。

尚未实现：流式生成、分块持久化、重叠切分、向量化、向量库、BM25、重排、检索引用、RAG效果评测、多用户权限、OCR、旧版.doc和自定义模型中转地址。API适配器和设置界面已实现并通过协议模拟测试；本轮没有使用真实供应商密钥进行付费端到端验收。

## 验证与开源

见 [验收记录](docs/ACCEPTANCE.md)。自动测试会产生 `test-results/`，其中的截图和临时数据不进入源码；`docs/screenshots/` 仅包含本项目的合成验收内容。

分块相关定向检查：`npm run test:chunks`。`npm test` 为按需全量检查，不要求每次改动重跑无关功能。

关键词检索相关定向检查：`npm run test:keyword`，只覆盖当前文档关键词命中/未命中/清空、原始块编号、过滤后的翻页与大小切换及本地数据边界。
